## 2. 证据链（按时间）

1. **双 dex 实证**：LSPosed 兼容日志 `/data/adb/lspd/log/modules_2026-11-19T20:25:16.559029.log` 里，同一 pid 在 20:26:19.950 加载 `/data/app/.../com.eta.fanqie.enhance.../base.apk`（`BUILD 1933`），20:26:20.106 又加载 `cache/lspatch/.../3061479279.apk`（旧、`AdUnlockTimeFloatingView`）。tag 都是 `VectorLegacyBridge`。

3. **决定性 A/B（21:05）**：`ps -A | grep -c "[v]ectord"` = **0**（框架守护进程完全没跑）时，删掉 cache 副本 → 冷启动番茄 → **仍重建** 61899 B / md5 `6212b65c…`。
   ⇒ 来源是 app 自己的 `base.apk`，与 Vector/LSPosed 无关。
4. **覆盖法有效（21:07）**：把 cache 副本换成已装的 1.9.33 apk（保持文件名、`chown 10404:20404`、`chmod 600`），冷启动后**没有被还原**（49611 B / md5 `2ca6d14e…`）。日志只剩 `[BUILD 1933]` 一套行为，旧模块的 `AudioHelper.j` / 语音拦截 / 时长伪装特征全部消失。
   ⇒ **LSPatch 只在文件缺失时释放 assets，文件存在时直接用**。这是当前最轻的修法。
5. **音频症状**：`playerapi/video_model/mget` 请求成功但**无后续音频流请求**；`AudioPlaybackConfiguration` 里 AudioTrack 已创建（44100Hz）却 `state=paused`、`position=0`。⇒ 应用层取流被拦，不是放不出声。

## 14. ★★★ 黑条真·解决：官方设置项写错库（2026-11-20 13:42，最终定案）
- **真因**：摩托罗拉官方有设置项 `live_content_type_disabled`，SystemUI 的 `ChipsSettingsController.access$updateAllChipsEnableState()` 从 **`com.motorola.android.provider.MotorolaSettings$Secure.getStringForUser()`** 读它，按 `;` 分隔，含 `media` → `_mediaChipEnabled=false`（关媒体灵动岛），含 `flashlight` → 关手电筒芯片。这是 ROM 自带开关，ContentObserver 自动生效，**无需注入 SystemUI、无需改 flag、不重启、不影响其他 app 的通知类灵动岛**。
- **★ 关键坑：这个键在摩托罗拉私有库，不在标准 settings secure！**
  - 私有 provider authority = `com.motorola.android.providers.settings`（`/system_ext/priv-app/MotorolaSettingsProvider`，versionName=16）。
  - ❌ `settings put secure live_content_type_disabled media` → 写进标准 Android secure，SystemUI **根本不读** → 白忙（13:40 前面踩过，读回 standard secure 有 "media" 但黑条纹丝不动）。
  - ✅ 正确写入（需 root，shell uid2000 会报 `com.motorola.permission.WRITE_SECURE_SETTINGS` 拒绝）：
    ```
    su -c 'content insert --uri content://com.motorola.android.providers.settings/secure \
      --bind name:s:live_content_type_disabled --bind value:s:media'
    ```
  - 该 provider 查询语法特殊：key 放在 URI 路径里 `--uri .../secure/live_content_type_disabled`，用 `--where name=xxx` 会报 "Supported SQL" 错误。
  - 读回：`su -c 'content query --uri content://com.motorola.android.providers.settings/secure/live_content_type_disabled'` → `Row: 0 _id=317, name=live_content_type_disabled, value=media`。
  - 回滚：`su -c 'content delete --uri content://com.motorola.android.providers.settings/secure/live_content_type_disabled'` 或改回 `value:s:` 空。
- **验证**：写入前截图 `chk_1340.png` 顶部黑条明显；写入后 `chk_after_write.png`（3 秒后）顶部状态栏时间/信号/电量完全露出，黑条消失。`LiveContentPeek`/`LiveContentExpand` 窗口对象仍在（SystemUI 常驻），但媒体芯片已禁用不再渲染黑底。
- **反编译依据**：`dexdump.py --dex-dir sui_dex --dex classes2.dex --class com.android.systemui.statusbar.chips.ChipsSettingsController` → `access$updateAllChipsEnableState` 含字符串 `live_content_type_disabled`/`;`/`media`/`flashlight` + 调用 `MotorolaSettings$Secure.getStringForUser` + `_mediaChipEnabled`/`_flashlightChipEnabled` StateFlow。
- **★ 最终验证通过（13:44）**：番茄 `PlaybackState=PLAYING(3)`、前台/桌面均拍到，**黑条不复现**（`final_playing.png` 状态栏时间 13:44:33/信号/电量全正常）。这是最严格条件——此前所有 A/B 都是 PLAYING 下黑条才出现，故确证设置生效，推翻第 13 节"留给系统/无解"的旧结论。
- **⚠️ 副作用需用户知情**：`media` 是**全局按类型**禁用媒体灵动岛，不只针对番茄——其他 app（网易云/QQ音乐等）播放时的媒体胶囊也会不显示；但**通知类灵动岛（计时器/外卖/导航等）和 flashlight 芯片不受影响**（设置值只含 `media`，`ChipsSettingsController` 的 `_mediaChipEnabled` 只管媒体 chip）。系统级无法只按单个包名关媒体胶囊，除非注入 SystemUI（高风险，见方案③）。

## 15. ★★★ 最终认知定案：胶囊 = 黑条 = 同一形态，无第三种（2026-11-20 13:55）
- 用户澄清「之前的小窗」= 媒体胶囊本身、点击会放大成播放面板。实物验证：`content delete` 删掉 `live_content_type_disabled` 后 3 秒，**黑条立刻回来**（`top_crop.png` 裁剪证实 x70~1380 宽1310px 纯黑）——彻底证明 **黑色宽条 = 媒体胶囊 = 用户说的小窗，三者同一物**。
- 反编译穷尽 Motorola 灵动岛类（`com.motorola.systemui.notification.livecontent.*`）：只有 `live_content_type_disabled` 一个设置项，**无"默认展开/短窄样式/带封面"开关**。番茄是听书 app、MediaSession 走 MediaHost 宽条挂载（非音乐类的紧凑 pill），折叠态必然是撑满宽黑条。`LiveContentChipViewBinder`（短 chip）会被媒体宿主宽条盖掉。
- **结论：二选一，无第三条路**：① 有黑条=胶囊功能在（点击放大正常）；② 无黑条=状态栏干净但胶囊也没。切换只需 `su -c 'content insert/delete --uri content://com.motorola.android.providers.settings/secure/live_content_type_disabled --bind name:s:live_content_type_disabled --bind value:s:media'`（insert 禁/delete 恢复），ContentObserver 自动生效，无需重装/重启/动模块/碰播放。

## 16. ★★★★ 黑条真根源（2026-11-20 14:20）：空内容 Peek + 深色默认背景（反编译+图形层双证）
### 证据链（全部实测，非推断）
1. **SurfaceFlinger 铁证**：`dumpsys SurfaceFlinger` 图层树 `2b3caac LiveContentPeek#82 flags:0 a:1` —— **alpha=1、正在合成**。WindowManager 报的 `isVisible=false` 是假象（该窗口走 SurfaceControl，不信 WMS 标志）。
2. **像素实测**：黑条 y=30~120、x≈65~1375、**连续 1310px 纯黑（r/g/b 全<40，一个非黑像素都没有）**。说明不是有内容的卡片（有封面会有彩色像素），而是**空壳 + 纯色背景**。
3. **MediaData 是完整的**（推翻"无媒体数据"旧假设）：`adb shell dumpsys activity service com.android.systemui/.SystemUIService` 里 MediaDataProcessor → `MediaData(app=番茄畅听, artist=洪剑锋, song=003 我相信我儿子..., artwork=Icon(BITMAP 300x300), active=true, isPlaying=true, actions=[], appIcon=null)`。**有封面、有歌名** → 所以展开态正常。
4. **折叠 Peek 的内容源 ≠ MediaData**：`LiveContentInteractor.<init>` 里 `peekLiveContent = flowCombine(?, repository._peekLiveContent, ...)`；媒体走的是独立的 `_mediaLiveContent`（= MediaHost.hostView）。**Peek 的内容来自 `_peekLiveContent`（由通知构建的 ViewPack），媒体数据进不去 Peek 的内容槽**。
5. **渲染路径 = V2**：`pm list features` 有 `feature:com.motorola.live_content_v2` → `bindPeekView` 走 V2 分支（`LiveContentPeekView`：ImageView + 2×TextView + 2×FrameLayout 的 `LiveContentPeekViewBinding`），由 `LiveContentPeekViewBinder$bind$1` 从 `peekViewModel.peekContent` 填数据。**数据空 → 三个内容 view 全不显示**。
6. **★ 背景色硬编码在框架资源**：`LiveContentContainerView.<init>(4参)` 里 `const v1, #17171165` → `normalColorRes = 0x01060B3D`（framework 颜色资源）。`updateBackground()`：子view 若是 ColorDrawable 则取其色做 tint，否则用 `normalColorRes`。**内容空 → 用 normalColorRes → 深色模式（Night mode: auto，当前深色）下渲染成纯黑**。另 `LiveContentChipViewBinder.bind` 有 `setBackgroundColor(0xFF000000)` 硬编码纯黑。
### 根因结论（一句话）
**番茄播放 → SystemUI 判定"有媒体 live content"→ 挂出 Peek 胶囊（alpha=1）→ 但 Peek 的内容槽只认通知构建的 ViewPack（番茄通知无 motorola live content 数据，isLiveContent=false → ViewPack 空）→ 三个内容 view 全空 → 露出容器的深色默认背景 0x01060B3D → 视觉上就是一条纯黑胶囊。**
> 即：**媒体会话负责"让胶囊出现"，通知数据负责"填充胶囊内容"，番茄两者不匹配 → 空壳黑条。** 这与"通知 title/largeIcon/color 全空"是同一根因的两个面，但精确表述是「Peek 内容源=通知ViewPack，媒体数据不进Peek」。
### 处理可行性
- **只禁番茄不碰其他 app**：唯一精准 hook 点是 `LiveContentInteractor.requestAttachMedia(Z)V`（已反汇编，逻辑极简：`_mediaLiveContent.setValue(z ? MediaHost.hostView : null)`）。注入 SystemUI 后判断当前媒体会话包名==com.xs.fm 就强制传 false → 番茄不挂 Peek，其他 app 不受影响。**需 scope add com.android.systemui/0，风险中高（SystemUI 崩溃需重启恢复），本机未验证过注入系统进程**。
- **给胶囊补内容**：需伪造 Motorola live content 通知结构（peekViewStart/End/collapsedRemoteView 等私有 extras），v1.9.41 证明改通知 flags 无效，补结构难度极高、不保证成功。
- **全局 media 设置**：已实测「写 `live_content_type_disabled=media` → 黑条立即消失」，但**同时禁掉所有 app 的媒体胶囊**（用户明确拒绝）。
